This guide explains how BlogHub settings interact with Git branches and deployment.

## 1. Site settings you should configure first

Open `/admin/settings` and review:

- `Site name`
- `Tagline`
- `Site URL`
- `Language`
- `Logo`
- `Favicon`
- `Permalinks`
- `Continuous deployment (CD)`
- `Index categories`

Settings are stored in:

```text
public/site/settings.json
```

## 2. Permalink presets and custom patterns

Built-in presets include:

- `/:slug/`
- `/:year/:month/:day/:slug/`
- `/:year/:month/:slug/`
- `/archives/:id/`
- `/:category/:slug/`

Custom permalink tokens supported:

- `:slug`
- `:year`
- `:month`
- `:day`
- `:id`
- `:category`

## 3. Branch behavior in BlogHub

By default, content editing is a `develop` first workflow:

- posts, media, and theme saves commit to `develop`
- admin `Deploy` merges `develop` into `main`
- GitHub Pages deploy runs on `main`

## 4. What happens during login

When you log in, BlogHub validates token access and then ensures branch state:

1. Confirms `main` exists.
2. Creates `develop` from `main` if missing.
3. Merges `main` into `develop`.

If merge conflicts exist, login is blocked until conflicts are resolved on GitHub.

## 5. Deploy button behavior

`Deploy` is enabled only when `develop` is ahead of `main`.

When clicked, BlogHub calls GitHub merge API with:

- `base`: `main`
- `head`: `develop`

If branches are already synced, deploy is skipped.

## 6. CD toggle behavior

In current implementation:

- `CD` affects where **settings** saves go:
  - `cd: true` saves settings to `main`
  - `cd: false` saves settings to `develop`
- Post/media/theme commits still target `develop`.

So even with CD enabled, you may still need `Deploy` for non-settings changes.

## 7. GitHub Actions in this project

Two workflows are included:

1. `regenerate-content-develop.yml`
   - Trigger: push to `develop`
   - Runs `npm run generate`
   - Commits `public/generated/**`

2. `deploy.yml`
   - Trigger: push to `main`
   - Runs `npm run build`
   - Publishes `dist` to GitHub Pages

## 8. Recommended release routine

1. Edit posts/media/theme/settings in admin.
2. Confirm generated files are up to date on `develop`.
3. Click `Deploy`.
4. Verify GitHub Pages after `main` workflow completes.

## 9. Common issues

- Deploy fails with conflict: resolve merge conflicts between `main` and `develop` first.
- Content changed but site did not: `develop` was not deployed to `main` yet.
- New post missing: `public/generated` indexes are outdated.
