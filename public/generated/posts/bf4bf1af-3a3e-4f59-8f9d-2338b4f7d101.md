This guide walks through the full post workflow in BlogHub: create, preview, save as draft, publish, and edit.

## Before you start

- You can open `/admin` and you are logged in with a GitHub PAT.
- The repository has a `main` branch.
- `develop` exists, or BlogHub can create it during login.

## 1. Create a new post

1. Open `/admin/posts`.
2. Click `+ New post`.
3. Fill the main fields:
   - `Title`
   - `Body` (Markdown)
4. Fill post settings in the right sidebar:
   - `Slug`
   - `Date`
   - `Status` (`draft` or `published`)
   - `Excerpt`
   - `Tags` and `Categories`
   - `Featured image` (path like `/media/file.png`)

Notes:

- If title or slug is empty in a new post, BlogHub generates fallbacks before saving.
- URL preview at the top is computed from `settings.permalinks.post`.

## 2. Write content with the Markdown editor

The editor supports headings, lists, links, code blocks, tables, quotes, and horizontal rules.

Example snippet:

```markdown
## Why BlogHub

- Static output
- GitHub-backed edits
- Theme customization

```ts
console.log("hello")
```
```

## 3. Insert media into the post body

1. In the editor toolbar, click the image button.
2. Pick an item from the media library.
3. BlogHub inserts markdown automatically:

```markdown
![image](/media/your-file.png "image")
```

For non-image files, BlogHub inserts a link.

## 4. Preview before saving

Click `Preview` in the editor header.

- BlogHub opens a new tab with `?preview=true`.
- Draft content is loaded from local storage in that tab.
- You can preview unpublished changes without committing.

## 5. Save draft or publish

The save button label depends on status:

- `draft` status: `Save as Draft`
- `published` status: `Publish`

On save, BlogHub commits a markdown file to:

```text
public/posts/<post-id>.md
```

Commit messages are generated automatically, for example:

- `chore: save draft <id>`
- `feat: publish post <id>`

## 6. Edit existing posts

- Return to `/admin/posts`.
- Use search, status filters, and sort options.
- Click `Edit` to update fields or content.
- Click `Delete` to remove `public/posts/<id>.md` from the repo.

## 7. Make sure the post appears on the site

BlogHub runtime reads generated files under `public/generated/`.

If your new post is not visible yet:

1. Run `npm run generate` locally and commit generated files, or
2. Push to `develop` and let the `Regenerate content (develop)` GitHub Action update `public/generated/**`.

## Frontmatter reference

BlogHub post files use YAML frontmatter plus markdown body.

```yaml
---
id: "uuid"
title: "Post title"
slug: "post-title"
date: "2026-02-07"
status: "draft"
excerpt: "Short summary"
tags: ["tag1", "tag2"]
categories: ["guides"]
featured_image: "/media/hero.png"
seo_title: "Custom SEO title"
seo_description: "Custom SEO description"
---

Markdown body here.
```
